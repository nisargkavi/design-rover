# Design Rover 0.5.0

Keep the component map updated while editing with `bunx design-rover watch`.

- Watch refreshes observed component and token inventory after supported source changes settle. It polls complete file contents and the source manifest, covering additions, edits, deletions and renames.
- Approvals remain explicit. Approved or human-annotated records, rejected knowledge and pending policies stay unchanged and receive a review action when their evidence changes.
- CLI and MCP requests read the updated model. Existing freshness checks continue to report changes that still need a decision.
- Generated guidance stays unchanged by default; `watch --generate` opts into regeneration.
- Polling and stability delays are configurable with `--interval` and `--debounce`. `--json` emits newline-delimited events for automation.
- Invalid syntax and unreadable inputs stop a refresh before observations are saved; conflicting saves are retried. With `--generate`, observation updates can be saved before a guidance error, which is reported for retry. Approvals stay unchanged.
- SIGINT and SIGTERM stop cleanly after any in-progress write.

Run `init` before starting watch. Review deferred changes with `bunx design-rover diff --json` and use an explicit approval or rejection command for each decision.

Validation: 230 tests, 35 release-script tests, workspace typechecks, and installed-package watch/MCP smoke checks. Isolated copies of a Next.js portfolio (303 source/config files) and React browser extension (59 files) passed live add/edit, approval preservation and clean-shutdown checks. Their original projects stayed unchanged.
