# Design Rover 0.3.1

This patch improves first-run guidance and fixes issues found while checking a real React browser-extension project.

## Developer workflow

- `init` explains what was created, what needs review, which APIs are incomplete, and the next copyable Bun commands. Repeated initialization reports saved knowledge separately from newly observed counts.
- `diff` shows change IDs and individual approve/reject commands. `sync --yes` accepts observed updates without approving inferred rules; approval requires an explicit decision or `--approve`.
- Status and check output distinguish freshness, pending review, generated guidance and API resolution. Command-specific help is available for `init`, `sync` and `context`.
- The README focuses on getting started, agent usage and supported behavior. Detailed Git, development and release workflows live in linked documentation.

## Fixes

- Ordinary JSX classes and static conditional template branches now contribute component-token relationships. Tailwind 4 theme namespaces map to their supported static utilities, including variants and opacity modifiers. Token counts no longer treat a declaration alone as a use.
- Existing models can sync changed token links, usage and architecture observations. Context-only updates are distinguished from API contract changes.
- Tests and stories remain usage evidence but do not establish production reuse when classifying a component as shared.
- Short-lived canonical lock contention waits before failing, allowing concurrent queries while preserving consistent snapshots. Stale locks are not removed automatically.
- Image conventions use verified `next/image` imports. Native `<img>` elements receive neutral guidance in browser extensions and other React projects.

Run `bunx design-rover@0.3.1 diff` on an existing model to review changed observations. Initialization preserves existing decisions. External package types and CSS class contracts such as `.btn` variants remain outside complete API resolution; a clean check is not a comprehensive design or accessibility audit.
