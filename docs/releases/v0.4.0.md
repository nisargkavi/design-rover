# Design Rover 0.4.0

Agent context now checks whether saved design knowledge matches supported source observations before returning it.

- CLI `context` and MCP `get_context` check freshness by default. Packets report the check time, source drift, pending reviews and stale generated guidance separately.
- Stale observations include review and refresh commands with their working directory. Review the diff, then explicitly apply observed updates with `sync --yes` and request context again. Pending knowledge and protected removals still require explicit decisions.
- Retrieval preserves canonical knowledge, approvals, history, generated guidance and application source. Only the ignored evidence cache may be refreshed.
- Failed checks return actionable errors. Use CLI `--no-check-freshness` or MCP `checkFreshness: false` for an explicitly unchecked saved snapshot.
- Freshness metadata and actions stay within the requested response budget. The check covers supported observations at a point in time; rejected proposals remain suppressed.

Validation: 211 tests, 35 release-script tests, workspace typechecks, and an installed-package smoke test covering fresh-project initialization and stdio MCP. Isolated copies of a Next.js portfolio (303 source/config files) and a React browser extension (59 files) passed freshness detection and explicit-refresh checks with their original projects unchanged.
