# Design Rover 0.3.0

Design Rover now retrieves bounded design context for a task and resolves more component APIs from local TypeScript modules.

## Added

- `design-rover context` and MCP `get_context` share task/query and repository-path filters, result limits, and a character budget. Output includes source references and explicitly reports omitted records and decisions. Pending knowledge remains opt-in.
- Component props can resolve through local imports and re-exports. Records expose resolution status and issues instead of presenting unresolved APIs as complete.
- Local barrel exports preserve component identity and usage attribution. Cycles and ambiguous exports remain unresolved.
- GitHub Releases include the exact npm package tarball and `SHA256SUMS`. The workflow checks the tagged source against the public package before releasing assets.

## Install

From the project you want to analyze:

```sh
bunx design-rover@0.3.0 init
bunx design-rover@0.3.0 context "update the settings form" --path app/settings/page.tsx --max-chars 12000 --json
```

Requires Node >=20.19.0. Retrieval reads canonical knowledge; use `status` and review `sync` proposals to check freshness. An omitted decision still needs review. Type resolution is limited to scanned local modules and supported static forms; external package declarations and complex dynamic types remain unresolved.
